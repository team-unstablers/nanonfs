# 2026-05-09 — RFC 7530 reference audit + NFSStatus raw shift fix

- Ran a full audit of every `RFC 7530 §X` citation in source / tests / `CLAUDE.md` against the body of `docs/rfc7530.txt`. Audit driver and full table of corrections live in `llm_prompts/20260509-audit-rfc-reference.execution-log.20260509.xml`.
- Most common pattern was using the **op number as the §16 section number** (e.g. COMPOUND→§16.2, where §16.2 is actually CLOSE; ACCESS→§16.3, where §16.3 is actually COMMIT). RFC 7530's §16.N maps to op (N+2), so several dozen call sites had to be re-pointed. Coincidental matches (READ §16.23, WRITE §16.36, OPEN §16.16, etc.) were left alone.
- Other classes of correction:
  - Wrong chapter entirely. `stateid4` was variously cited as §3.3.12 / §8.1.3 — neither exists. Real definition is §2.2.16, semantics in §9.1.4.
  - Hallucinated subsections. `§3.3.5` (change_info4), `§3.3.13` (writeverf), `§5.11` (delegation ACE) — none exist. §3.3 only has subsections .1-.3, §5 only goes to .10.
  - 4.1-only constructs cited as 7530. `OPEN4_SHARE_ACCESS_WANT_*` is RFC 5661 (NFSv4.1) only — RFC 7530 OPEN4args.share_access has no high-bit hints. CLAUDE.md 2026-05-03 work-log entry corrected accordingly.
  - `NFS4ERR_WRONG_TYPE = 10083` does not exist in RFC 7530 (added in RFC 5661). The code's `wrongType` case maps onto `NFS4ERR_BADTYPE = 10007` via `asStatus`, so the comment was fixed to match the wire reality.
- **Bigger latent bug found and fixed**: `Sources/NanoNFS/Wire/NFSv4Constants.swift` `NFSStatus` had its 10037–10043 range shifted by one (`lockNotGranted = 10037` was the slot for `NFS4ERR_LOCKS_HELD`; `badowner = 10040` was the slot for `NFS4ERR_BADCHAR`; etc.). Only `.badowner` was actually used (3 sites in `CompoundDispatcher.swift` — SETATTR/CREATE/OPEN owner-string parse failure), which means clients had been receiving `10040 (NFS4ERR_BADCHAR)` whenever the server actually meant `NFS4ERR_BADOWNER`. Re-aligned the entire 10037–10043 range to RFC 7530 §13.1, removed two invented case names (`lockNotGranted` and `lockOldStateid` — neither exists in 7530), and added the previously-missing `lockNotSupp = 10043`. `swift test` 65/65 still green.
- **Why this matters going forward**: previous CLAUDE.md note "NFS4ERR_LOCK_NOTSUPP (raw 가 같을 위험)" assumed a collision with `NFS4ERR_OP_ILLEGAL = 10044` — that concern was never real (10043 vs 10044), and the case is now properly defined.
- **Process decision (user request)**: hardened the §4 RFC reference policy with a mandatory anti-hallucination rule that requires a direct lookup in `docs/rfc7530.txt` before *writing* any new RFC citation (not only when the user happens to quote one). Three concrete trap categories — op-number-vs-§16 offset, data type chapter (§2 vs §3.3 / §8.1), and 4.1-only features (RFC 5661) misattributed to 7530 — are listed inline so future agents do not have to re-derive them. This was the missing rail that made the present audit necessary in the first place.
